# План улучшений YouTube SpeedX

Дата: 2026-02-04

## Цели
- Устранить выявленные риски и баги.
- Свести поведение скоростей к единому стандарту.
- Сделать поведение лимита 60 FPS предсказуемым.
- Повысить стабильность на Rutube.

## Пошаговый план

1. Подготовка
   - Зафиксировать текущее поведение и ожидаемые сценарии.
   - Описать, какие из изменений являются исправлениями багов, а какие — улучшениями.

2. Единая нормализация скорости
   - Добавить функцию `normalizeSpeed(value)` с единым округлением (например, до 2 знаков).
   - Применить ее в:
     - `YouTubeAdapter.applySpeed`
     - логике Speed Boost
     - Generic/Rutube `applySpeed` при необходимости

3. Исправление шага 0.05
   - Убрать `toFixed(1)` в `YouTubeAdapter.applySpeed`.
   - Применить округление из `normalizeSpeed`.

4. Лимит 60 FPS и горячие клавиши
   - Определить политику поведения: strict или soft.
   - Если strict:
     - В `changeResolution` использовать `getAvailableQualityData()` без `true`.
     - Либо применить фильтр вручную к `availableQualityData`.
   - Если soft:
     - Явно описать это в README и UI.

5. Rutube: предотвращение утечек слушателей
   - В `RutubeAdapter.onInit` проверять `video.dataset.rateListenerAttached`.
   - Добавлять `ratechange` только один раз.

6. Валидация числовых настроек
   - Перед сохранением проверять `Number.isFinite`.
   - При ошибке возвращать значение по умолчанию или текущее.
   - Применить `clamp` для диапазонов speed/step/progress opacity/boost.

7. Уборка мусорных полей конфигурации
   - Удалить строки, связанные с `DECREASE_KEY/INCREASE_KEY`, из `saveConfig`.

8. Тест-план (ручной)
   - YouTube: скорости 1.25, 1.30, 1.35 при шаге 0.05.
   - Speed Boost: корректность отображения и возврат к исходной скорости.
   - Проверка лимита 60 FPS + hotkeys.
   - Rutube: смена видео и отсутствие повторных listener-ов.

9. Документация
   - Обновить README: поведение лимита 60 FPS, форматы скоростей.
   - Добавить краткий список изменений в CHANGELOG.
